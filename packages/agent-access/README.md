# Agent Access contract and verifier package

Private workspace package for the Agent Access reference. It does not publish a generic SDK or replace the historical HITL schema entrypoint.

`contracts.ts` owns the new application DTOs. Types are inferred from Zod; `AGENT_ACCESS_JSON_SCHEMAS` derives the profile/OpenAPI representations, using input mode for request contracts. Runtime validation additionally enforces arithmetic snapshot totals. `snapshotDigest` uses JCS and SHA-256 over the validated snapshot.

`KeycloakAuthenticator` validates signed Keycloak access tokens, ES256 DPoP, required resource-server nonces, persistent replay consumption and noncached authenticated introspection. Effective scopes are the intersection of signed-token and introspection scopes. `observed_at` is captured immediately before introspection using the persistence clock, so the freshness budget includes network latency; token and proof expiration are checked again after completion. Introspection bodies are streamed with a 64 KiB limit and cancelled upon overflow. Token issuer/audience and all provider endpoints come from trusted configuration. Only an explicit loopback development option permits HTTP. Deployments must restrict which OAuth clients may obtain this audience and its scopes at the authorization server; the authenticator binds the signed `azp` to introspected `client_id`, while the service binds authority to the independently confirmed client/key enrollment.

`PersistentProofStore` must be backed by shared persistent state. Its `now()` method supplies the authoritative clock used by nonce/replay cleanup and business authorization. Production verifiers use this clock by default; optional clock overrides are for tests and must remain in the same clock domain. `consumeReplay` is an atomic insert-if-absent until its exclusive deadline. Proofs are rejected at that exact deadline, including after asynchronous verification or persistence; cleanup may then remove the row. Nonces are bound to the DPoP thumbprint and can be reused during their 60-second lifetime; every request still needs a unique proof JTI. The proof freshness window is 60 seconds with at most 30 seconds clock skew. The resource-server nonce namespace is independent of the authorization server's nonce namespace. Store failure throws a sanitized 503 and never grants authority. Services must enforce IP/global admission limits before invoking either verifier, including nonce challenges and rejected requests, then apply account/grant quotas after authentication.

The Public Web binding supports Ed25519, dictionary `Signature-Agent` members with `directory` discovery, and signed GET/HEAD reads only. It requires signed method, authority, full target URI and the same dictionary member as the signature label. It does not grant private access. Production directory fetching enforces HTTPS, TLS verification, a validated and pinned public DNS address, no redirects, 2 seconds, 64 KiB, 32 keys, 300-second maximum cache lifetime, 30-second negative caching and bounded unknown-key refresh. Private, link-local, mapped and transition IP ranges are rejected conservatively. In-process coalescing is bounded; a multi-process deployment must wrap `DirectoryResolver` with the reference's shared directory-cache coordinator. The `transport` override exists for controlled tests and must not be configured from requests.

The reference directory coordinator uses the database clock for cache expiration and refresh cooldowns, including its upstream `SafeDirectoryResolver` (which accepts an asynchronous clock). A 30-second lease is renewed after the quota check and checked before fetching. Publication locks and verifies the current, unexpired lease owner in the same database statement for both successful and failed lookups. A displaced owner cannot restore stale keys or replace a newer result with an outage. No database lock is held during HTTPS. Concurrent callers use a 2.5-second monotonic contention budget, with database statement timeouts enforced separately, and can retry after a crashed owner's lease expires.

`createAuthorizationRequest`, `exchangeAuthorizationCode`, `completeBrowserLogin` and `refreshDPoPTokens` implement PKCE/OIDC/DPoP client operations through oauth4webapi. The caller must persist the authorization attempt server-side, bind it to its browser session, expire it and consume it once before exchange. Browser identity is validated from an ID token; email is exposed only when verified. `authenticatedAgentFetch` retries an RS nonce challenge once with a fresh proof. Callers preserve business idempotency keys across transport retries.

Run `pnpm --filter @hitl-protocol/agent-access test`, `typecheck`, and `build`. Tests use actual signed JWTs and HTTP signatures with controlled provider/network fixtures; these fixtures do not replace the separate real-Keycloak and PostgreSQL acceptance suite.
